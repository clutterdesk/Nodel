Cross-Compiling Nodel for Windows

How the clang-cl + xwin build produces a Windows x64 nodel_test.exe on macOS

Overview

Nodel's unit tests can be built for Windows x64 without a Windows machine. The build targets the MSVC ABI, so the resulting binaries link against the same C/C++ runtime as code built with Visual Studio. It uses three pieces:

  • clang-cl: LLVM's compiler, which accepts MSVC-style options and emits Windows object files.
  • lld-link: LLVM's linker for Windows executables (PE/COFF).
  • xwin: a tool that downloads Microsoft's CRT headers and libraries and the Windows SDK, and lays them out for use on a non-Windows host.

The Python extension, RocksDB support and the Doxygen docs are skipped when cross-compiling.

Quick start

brew install llvm ninja
cargo install xwin --locked     # Rust < 1.85: cargo install xwin --version 0.6.5 --locked
xwin --accept-license --arch x86_64 --cache-dir ~/.xwin-cache \
     splat --include-debug-libs --output ~/.xwin

cmake --preset windows-x64
cmake --build --preset windows-x64

Running xwin with --accept-license means you accept Microsoft's license for the CRT and SDK. You only need to run it once, or again to update the SDK; the build itself doesn't run xwin.

How the toolchain file works

  1. Target system. Sets CMAKE_SYSTEM_NAME Windows and AMD64, which makes CMake treat the build as a cross-compile (CMAKE_CROSSCOMPILING is true and WIN32 is set).
  2. Locations. LLVM_ROOT, LLD_ROOT and XWIN_DIR come from a -D option, then an environment variable of the same name, then the first default path that exists. Configuring stops with an error if XWIN_DIR doesn't contain a splat.
  3. Tools. clang-cl is the C/C++ compiler, lld-link the linker, llvm-lib the archiver, and llvm-rc/llvm-mt the resource and manifest tools. The target triple is x86_64-pc-windows-msvc.
  4. Headers. Each xwin include directory (CRT, ucrt, um, shared, winrt) is passed with /imsvc, which makes them system headers so their warnings stay quiet.
  5. Libraries. /libpath: entries for the CRT, um and ucrt x86_64 library directories are added to the executable, shared and module linker flags.
  6. Runtime. Uses the dynamic CRT (/MD, or /MDd for Debug), which matches googletest's gtest_force_shared_crt.
  7. Isolation. Library, include and package searches are confined to the xwin directory, so host packages such as Homebrew RocksDB or Python can't leak into the Windows build.

Adjustments in CMakeLists.txt

  • ZipLib is an add_library(nodel_ziplib STATIC …) target, not a call to its Makefile, which hardcoded clang and had no Windows target. On Windows it compiles the Win32 lzma sources (the list from lzma.vcxproj); elsewhere it uses extlibs/lzma/unix. It's pinned to C++11, matching the Makefile.
  • Threads: Threads::Threads replaces -pthread.
  • Warnings: NODEL_WFLAGS (GCC/Clang syntax) is only passed to compilers that aren't MSVC-style.
  • Host-only parts: RocksDB and the Python extension are skipped when CMAKE_CROSSCOMPILING is set, and Doxygen is optional.
  • Third-party workarounds (vendored sources are left unmodified):
    • lzma's CpuArch.c is compiled with /FIintrin.h, because it calls __cpuid, which MSVC treats as a built-in but clang-cl needs declared.
    • googletest gets -Wno-character-conversion under clang-cl 21 or later. It builds with warnings-as-errors on MSVC, and that warning fires in gtest-printers.h.

Running the result

build-win64/nodel_test.exe imports MSVCP140.dll, VCRUNTIME140.dll, VCRUNTIME140_1.dll, the api-ms-win-crt-* DLLs and dbghelp.dll. To run it, copy build-win64/nodel_test.exe and build-win64/test_data/ to a Windows 10 or later machine with the Visual C++ Redistributable (x64) installed, or run it under Wine. To check the output without running it: 

file build-win64/nodel_test.exe
llvm-readobj --coff-imports build-win64/nodel_test.exe

Overrides

cmake --preset windows-x64 -DLLVM_ROOT=/path/to/llvm -DLLD_ROOT=/path/to/lld -DXWIN_DIR=/path/to/xwin
# or
export LLVM_ROOT=… LLD_ROOT=… XWIN_DIR=…

Tool paths are cached in build-win64/CMakeCache.txt. Delete build-win64/ after changing them.

Troubleshooting

SymptomCause and fix
MSVC CRT/SDK not found in XWIN_DIRRun the xwin … splat command above, or set XWIN_DIR.
xwin fails with Cross-device link (os error 18)xwin caches in the current directory by default and can't move files across volumes. Pass --cache-dir on the same volume as --output.
cargo install xwin fails parsing the manifest (edition 2024)The newest xwin needs Rust 1.85 or later. Run rustup update, or install --version 0.6.5.
brew install lld runs for hoursHomebrew is compiling LLVM from source because no prebuilt package exists for your Mac. Stop it and use the rustup lld-link, which the toolchain finds automatically.
Homebrew clang-cl fails with Library not loaded: …libz3…z3 was upgraded under LLVM. Run brew reinstall z3 llvm, or point /usr/local/opt/z3 back at the version LLVM was built against.
