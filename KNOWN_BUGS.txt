KNOWN BUGS
==========

Checklist of every known bug in nodel. Tick an item ([ ] -> [x]) when it is
fixed and has a passing regression test, and add the commit.

Rebuilt 2026-10-22 at commit 7f0ef29933. Locations are given by function
name because line numbers drift.

IDs
  O = nodel/core/Object.hxx (incl. OPath, Subscript, DataSource, visitors)
  K = nodel/core/Key.hxx and the support headers it uses
  P = Python extension (pyext/)
  D = nodel/kvdb (RocksDB data source)
  T = test-suite failures whose cause is not yet known
  O1-O10 keep the numbers of the original Object bug list, which commit
  messages refer to ("Fix Object bug #9").

Tags
  [DEFINITE]  Wrong behaviour that has been reproduced, or is certain from
              the code.
  [LIKELY]    Probably a bug, but not reproduced, or it depends on intended
              behaviour that is not documented.
  [FRAGILE]   Works today, but only by accident (layout coincidences, code
              that is never instantiated, unchecked input). Will break on an
              unrelated change.
  [CONFIRMED] Reproduced, by an ObjectBug/Key test or an ASan probe.
  [ASan]      The regression test only catches the bug when built with
              AddressSanitizer; it passes in a normal build.


OPEN
====

Object
------

[ ] O11 [DEFINITE] [CONFIRMED] Self-assignment frees the object first
    Object::operator=(const Object&) and operator=(Object&&) call
    dec_ref_count() before copying. `x = x` on the only reference to a
    container frees it and then reads from it; a self-move leaves x empty.
    The same happens when assigning from a reference to an element inside
    the container being freed.
    Tests: ObjectBug.SelfCopyAssign (crashes), ObjectBug.SelfMoveAssign.

[ ] O13 [DEFINITE] [CONFIRMED] Subscript assignment breaks after the
    subscript has been read
    Subscript::operator= / resolve():
    - resolve() replaces m_obj with the looked-up value, so assignment then
      calls m_obj.parent().set(m_sub, ...).
    - If that value is a number, nil or missing, its parent is nil and set
      throws. E.g. reading s = obj["x"] and then doing s = 5 throws.
    - For Subscript<OPath>, the full path is applied to the leaf's parent
      instead of the original container.
    Tests: ObjectBug.SubscriptAssignAfterRead,
    ObjectBug.SubscriptPathAssignAfterRead.

[ ] O14 [DEFINITE] OPath::parse_brace_key reads past the end of the input
    - Unquoted branch: `for (; it != spec.cend() && c != ']'; ++it, c = *it)`
      dereferences end() when the closing ] is missing.
    - Quoted branch: after consume_whitespace, `*it != ']'` reads end() for
      input like "['a'".
    Tests: ObjectBug.ParsePathMissingCloseBracket,
    ObjectBug.ParsePathQuotedKeyMissingCloseBracket [ASan].

[ ] O15 [DEFINITE] [CONFIRMED] JSON output loses the comma before a bound
    object
    WalkDF::next pushes a data-source object's cached value with
    FIRST_VALUE and drops the original event, so a bound object that isn't
    the first child gets no ", " before it.
    Test: ObjectBug.JsonSeparatorBeforeDataSource.

[ ] O16 [DEFINITE] [CONFIRMED] Pretty JSON one-liner depth leaks
    JsonVisitor increments the one-liner depth for any value whose key is a
    one-liner key, but only decrements at the end of a container. A scalar
    under such a key turns off pretty-printing for the rest of the output.
    Test: ObjectBug.JsonPrettyOneLinerKeyOnScalar.

[ ] O17 [DEFINITE] [CONFIRMED] Equality is one-sided with bound objects
    Object::operator== / operator<=>: bound == 5 loads the data and
    compares, but Object{5} == bound returns false, and <=> throws.
    Test: ObjectBug.DataSourceComparisonIsSymmetric.

[ ] O18 [DEFINITE] [CONFIRMED] Map equality treats missing keys as nil
    Map comparison in Object::operator==: a missing key reads as nil, so
    {a: nil} == {b: 1} is true.
    Test: ObjectBug.MapEqualityMissingKeyVsNil.

[ ] O19 [DEFINITE] [CONFIRMED] Object::hash() disagrees with == for floats
    INT 1 and FLOAT 1.0 compare equal but hash differently (std::hash of
    the double's bits), which breaks hash containers of Objects. Key had
    the same bug (K2); its fix, Key::float_hash, can be reused.
    Test: ObjectBug.HashConsistentWithEquality.

[ ] O20 [DEFINITE] OPath(const StringView&) only checks its input with
    assert
    In release builds an empty or all-whitespace spec reads *it at end().

[ ] O21 [DEFINITE] Floats are written with 15 significant digits
    float_to_str (support/string.hxx) uses "%.15g", but a double needs 17
    digits to round-trip. Object::to_str, JSON output (JsonVisitor) and
    Key::to_str/to_step/to_json all lose precision: 0.1 + 0.2 is written as
    0.3 and reads back as a different value.

[ ] O22 [FRAGILE] clear_parent() reaches a data source through the ANY
    pointer
    Object::clear_parent, DSRC case, uses m_repr.pany->m_parent instead of
    m_repr.ds->m_parent. Works only because both classes keep m_parent at
    the same offset. (set_parent's DSRC case is correct.)

[ ] O23 [FRAGILE] id() reads a sorted map through the ordered-map pointer
    Object::id, SMAP case, uses m_repr.pom instead of m_repr.psm. Works only
    by the same kind of layout accident.

[ ] O24 [FRAGILE] Some Subscript methods won't compile when used
    Subscript::key() calls m_sub.tail(), which OPath doesn't have (it has
    leaf()). keys(), items() and values() call Object methods that don't
    exist. They only fail if someone instantiates them.


Key and support
---------------

[ ] K7 [LIKELY] NaN keys can be inserted but never found
    Key(NaN) != Key(NaN), so a NaN key in a map can't be looked up, and
    each insert adds another entry.

[ ] K8 [DEFINITE] [CONFIRMED] Key::to_json() writes `nil` for a nil key
    Not valid JSON; should be `null`. JsonVisitor uses key.to_json() for
    map keys.

[ ] K9 [DEFINITE] [CONFIRMED] Key::to_bool() returns true for nil
    The default case returns numeric_limits<Int>::max() (copied from
    to_int), which converts to true.

[ ] K10 [DEFINITE] [CONFIRMED] Key::to_step() produces paths OPath can't
    read back
    - Only keys containing `"`, `.` or a space are quoted, so "a[0]" comes
      out as `.a[0]`, which parses as key "a" then index 0. Any character
      parse_dot_key doesn't accept (not alnum or _) has the same problem.
    - The empty string comes out as `.`, or nothing at all when is_first.
    - Floats lose precision (O21).

[ ] K11 [LIKELY] operator<<(ostream, Key) doesn't match Key::to_str()
    Prints bools as 1/0 and floats with the stream's default 6-digit
    precision, while to_str prints true/false and 15 digits.

[ ] K12 [DEFINITE] Key::get_repr_ix<T>() has no fallback return
    is_type<int>() or is_type<StringView>() flows off the end of a
    non-void function (UB).

[ ] K13 [FRAGILE] Mismatched friend declaration for ""_key
    The friend declares `operator ""_key(const char*)`, a raw literal
    operator that is never defined; the real one takes (const char*,
    size_t). Something like 123_key would compile and fail to link.

[ ] K14 [FRAGILE] Key{"abc"} doesn't compile
    Ambiguous between the String and StringView constructors; callers must
    use ""_key or an explicit String.

[ ] K15 [LIKELY] str_to_int / str_to_uint return garbage on bad input
    support/string.hxx: on a parse error they only ASSERT, so release builds
    return an uninitialized value. Used by Key::to_int/to_uint,
    OPath::parse_brace_key and kvdb deserialization.

[ ] K16 [FRAGILE] String keys only work within one thread
    Intern tables are thread-local, and string keys compare and hash by
    pointer, so a string key made on one thread never equals the same text
    made on another. By design (Objects are not thread-safe even for
    reads), but nothing detects misuse: lookups just miss.

[ ] K17 [FRAGILE] Interned strings are never freed
    intern_string allocates a copy per distinct string and never deletes
    it, even when its thread's table is destroyed. Unbounded key domains
    (e.g. keys parsed from data) grow memory without limit.


Python extension
----------------

[ ] P1 [DEFINITE] [CONFIRMED] Python slice assignment orphans or aliases
    the assigned values  (was Object bug #10)
    pyext/NodelObject.cxx, NodelObject_mp_ass_subscript, slice branch.
    Confirmed by replicating the extension's steps in C++; the extension
    itself was not rebuilt.
    The extension converts the value with Support::to_object(), calls
    clear_parent() on each element "to prevent copying", then calls
    self_obj.set(slice, nd_vals).
    - Python list value, e.g. lst[0:1] = [[], []]: to_object() builds a
      temporary nodel list. The values go into lst uncopied, then the
      temporary's destructor clears the parent of every element it holds,
      so the values in lst have no parent (parent() is nil, path() is
      wrong, and assigning one elsewhere won't copy it).
      Regression from the O3 fix: step +/-1 used to copy values with no
      parent, which accidentally avoided this. |step| > 1 was already
      broken.
    - Nodel object value, e.g. lst2[0:1] = other: to_object() returns
      `other` itself, so clear_parent() detaches other's own elements while
      they are still in other. They are now inserted uncopied, so lst2 and
      other share them: other[0]['k'] = 1 also changes lst2[0].
    Suggested fix: only clear parents when to_object() produced a new
    temporary container (not for a NodelObject value), and release the
    temporary's elements without clearing their parents afterwards, as
    DataSource::set(Slice) does.


[ ] P2 [LIKELY] In-place operators on bound values don't reach the data
    source
    pyext/NodelObject.cxx in-place number/string operators (+=, -=, ...,
    string slice assignment and *=). Object::type() reports the cached type
    of a bound Object, so these take the plain INT/UINT/FLOAT/STR branches:
    - Since the O12 fix, `obj.as<T>() op= v` changes the cache, but nothing
      calls set_unsaved(), so save() doesn't write it.
    - The float branches use `obj = obj.as<T>() + v`, which replaces the
      Python handle with an unbound value, detaching it from the source.
